## What it means

The type check follows JSON Schema. A schema that leaves `type` out imposes no
type constraint, so any value passes it. A schema whose `type` names something
JSON Schema does not know, such as `"uuid"`, is not a valid schema at all. That
is a defect in the node type, not in the workflow: the node type cannot be built
(SCH-24), and its config is not judged against a schema it does not have (R6.j).
The author is never charged with an error they cannot fix.

R6.d shares its code and locator with R6.e through R6.h, and all five run in
one fixed order, type first, stopping at the first violation. A value that
breaks two of them at once is charged with one error, for the constraint
checked earliest. Stopping early changes which error the author reads, never
whether the value is refused.

## Example

```json title="A key's declared schema with no type" verdict="stored"
{"untyped": {}}
```

```json title="The config value assigned to it" verdict="accepted"
{"untyped": ["anything"]}
```

A schema with no `type` holds the value to no type, as JSON Schema does.
