## What it means

A dynamic port definition carries a `name` and a `label`, and can carry a
`dataType`. Leaving `dataType` out is not the same as refusing the
definition: it is read as `mixed` instead. An authoring surface never records a
control lane as a dynamic port's `dataType`: a dynamic port is a value port by
definition, so a lane that exists only to route control has no place there.

That constraint is on what an authoring surface produces. A definition that
arrives another way with any other `dataType` is not refused, and nothing
downstream checks a dynamic port's declared type against the value it actually
carries.

## Example

A definition with a `dataType` of its own choosing still resolves:

```json title="A definition with dataType object" verdict="accepted"
[{ "name": "alpha", "label": "Alpha", "dataType": "object" }]
```

```json title="What resolving it still returns" verdict="unaffected"
{ "alpha": "a value" }
```
