## What it means

A gateway's configured branches, not the value it happens to emit, decide which
output port is real: an entry without a usable name is dropped before any
comparison runs, so it can never be matched or emitted. Matching an outcome
against what survives uses the conventions' equal values, the same comparison
JSON Schema's `const` makes: `true` matches only a branch configured with `true`,
never `1` or `"true"`, and `"Yes"` matches only `"Yes"`, never `"yes"`. No
conversion is made, so every implementation, in every language, picks the same
branch.

Where nothing configured matches, the gateway is not free to fall back to
whatever it would have said with no configuration at all: the outcome ends up on a default branch that receives it, or on a routable error. A name that answers to no port silently gates off everything downstream,
with nothing said.

## Example

A gateway configured with branches named `Yes` and `No`, given a `true`
outcome:

```json title="The gateway's inputs: the outcome and its configured branches" verdict="configured"
{"value": true, "branches": [{"name": "Yes", "value": true}, {"name": "No", "value": false}]}
```

```json title="The active_branches output" verdict="emitted"
["Yes"]
```

The renamed port, not a hardcoded `true`, is what leaves the gateway — an edge
drawn from `Yes` is the only one that can be reached.
