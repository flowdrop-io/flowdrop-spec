## What it means

A dynamic port carries none of the machinery an ordinary port carries: no
default exposure, no per-instance override, nothing edge validation can weigh
a wire against. The missing machinery does not fall on the cautious side —
it is not treated as hidden. A dynamic port is always wireable, and a value
produced under its name reaches the node's output exactly as produced,
because there is no schema entry to strip it against.

A dynamic port is not declared by the processor, but it is defined on the
node and stored with it, so it is known when the workflow is saved. A
workflow's interface can therefore bind one: a value supplied for the
interface input is delivered to it, and a value produced on it can be
returned as an interface output. Where the entry declares no schema of its
own, its contract accepts any value and sits on the port's lane (MAN-5,
MAN-21).

## Example

A node type hides one of its declared outputs. Alongside it, the node also
produces a value under a name the type never declared at all:

```json title="A node's output before exposure is applied" verdict="produced"
{"result": "ok", "dynamic_field": "kept", "ssn": "secret"}
```

```json title="What reaches the caller" verdict="kept"
{"result": "ok", "dynamic_field": "kept"}
```

`ssn`, a declared output the node type does not expose, is the one key
removed. `dynamic_field`, declared nowhere, has no schema entry to be removed
against, so it passes through untouched.
