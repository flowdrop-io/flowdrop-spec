## What it means

A JSONPath query can come back empty-handed in two quite different ways: it
runs cleanly and matches nothing, or it never runs at all because the string
does not compile or the engine fails. Only the first is a miss. A miss hands
back whatever default the caller supplied, `null` if none was given, and says
that nothing matched. An error is reported as an error and never turns into the
default, so a typo in a query cannot pass for data that simply is not there.
What the caller can also always tell is whether the query matched: a query that
matches a stored `null` returns that `null` and reports a match, never the
default.

## Example

Two queries against the same data, with the same supplied default:
`$.store.nonexistent`, which compiles and runs but matches nothing, and
`$.[invalid`, which cannot compile.

```json title="What the query that matches nothing returns" verdict="fallback"
"fallback"
```

The query that cannot compile returns no value at all: it is reported as an
error, and a node evaluating it fails (LANG-22).
