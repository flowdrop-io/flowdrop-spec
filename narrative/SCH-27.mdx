## What it means

Only two things are left out: a default the port does not have, and a display
order of `0`. `exposedByDefault` is never left out, `true` included (CFG-2). Nothing a caller might read as falsy is
left out on those grounds. A default value of `null`, `false`, an empty string
or an empty list is still a default the author set, and it is emitted; a display order of a negative number diverges from `0` just as much
as a positive one does, and is emitted too. A client that treats "absent" as
loosely as "falsy" reintroduces exactly the ambiguity the divergence rule
was meant to remove.

## Example

A port with neither a default nor an explicit order serialises to the six core
keys and its exposure:

```json title="A port with no default and no explicit order" verdict="omitted"
{
  "id": "plain",
  "name": "Plain",
  "type": "input",
  "dataType": "string",
  "required": false,
  "description": "",
  "exposedByDefault": true
}
```

A port whose default is the literal value `false` still carries the key:

```json title="The defaultValue emitted when the default is literally false" verdict="kept"
false
```

And a negative display order is emitted the same as a positive one:

```json title="The displayOrder emitted when the order is -5" verdict="kept"
-5
```
