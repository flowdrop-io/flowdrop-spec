## What it means

A dynamic port starts life as configuration on one node, but once DYN-8 lays it
over the node's schema there is nothing left to tell it apart. It is exposed by
default, an author can hide it like any other port, an edge into a hidden one
is refused, a hidden dynamic output is stripped from the node's result, and a
workflow's interface can bind it. Rules that judge ports do not mention dynamic
ports, because they do not need to.

## Example

A node defines a dynamic output `summary`, and the instance hides it:

```json title="The node's raw result" verdict="produced"
{"result": "ok", "summary": "draft"}
```

```json title="What the result delivers" verdict="stripped"
{"result": "ok"}
```
